# Два бота на одном сервере без зависаний

## Важно: версия aiogram на сервере

Если при запуске видите **`ModuleNotFoundError: No module named 'aiogram.client.default'`** — на сервере стоит старая aiogram. Варианты:

1. **Обновить (рекомендуется):** в папке бота выполнить  
   `pip install -U 'aiogram>=3.2'`  
   или  
   `pip install -r requirements.txt`

2. **Без обновления:** в коде уже есть обход: бот запустится с `Bot(token=...)` без Markdown по умолчанию (часть сообщений может без разметки).

## Почему зависало

1. **Подключение к БД без таймаута** — при медленной сети или Supabase `psycopg2.connect()` мог висеть очень долго.
2. **Инициализация БД в основном потоке** — блокировала event loop aiogram, бот не реагировал пока шло подключение и CREATE TABLE.
3. **Оба бота стартуют одновременно** — два подключения к одной БД в один момент, возможна конкуренция при создании таблиц.
4. **Буферизация вывода** — в логах ничего не видно, кажется что «висит».

## Что сделано в коде

### 1. Таймаут подключения к БД (signal-bot-1 и signal-bot-2)

В `database.py` в вызове `psycopg2.connect()` добавлен **connect_timeout=15** секунд. Если за 15 секунд подключиться не удалось — будет ошибка, процесс не зависнет.

**Во втором боте** в `database.py` нужно добавить так же:
```python
psycopg2.connect(settings.DATABASE_URL, connect_timeout=15)
```

### 2. Инициализация БД в отдельном потоке (signal-bot-1)

В `bot.py` вызов `init_db()` выполняется через `run_in_executor(None, init_db)`. Event loop не блокируется, бот быстрее переходит к polling.

**Во втором боте** в `bot.py` стоит сделать так же:
```python
loop = asyncio.get_event_loop()
await loop.run_in_executor(None, init_db)
```

### 3. Скрипт запуска с задержкой и небуферизованным выводом

В `start_both_bots.sh`:
- Сначала запускается Bot 1.
- **Пауза 5 секунд** — затем запускается Bot 2. Так оба не бьют в БД одновременно.
- Запуск через **python3 -u main.py** — вывод без буфера, в логах сразу видно, на каком шаге процесс.

## Как запускать на сервере

### Вариант A: один скрипт (nohup)

Скопируйте обновлённый `start_both_bots.sh` на сервер в удобное место (например в `$HOME` или в папку SignalBot1). Задайте пути, если они другие:

```bash
export BOT1_DIR=$HOME/SignalBot1
export BOT2_DIR=$HOME/Signalbot2
chmod +x start_both_bots.sh
./start_both_bots.sh
```

Проверка:
```bash
tail -f ~/bot1.log
tail -f ~/bot2.log
```

Остановка:
```bash
pkill -f "SignalBot1.*main.py"
pkill -f "Signalbot2.*main.py"
```

### Вариант B: systemd (рекомендуется для продакшена)

Два отдельных сервиса: автостарт после перезагрузки, перезапуск при падении, логи в journal.

1. Создайте файлы сервисов (подставьте свой пользователь и путь к проекту).

**/etc/systemd/system/signal-bot-1.service:**
```ini
[Unit]
Description=Signal Bot 1 (main menu, payments)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=YOUR_USER
WorkingDirectory=/home/YOUR_USER/SignalBot1
ExecStart=/home/YOUR_USER/SignalBot1/venv/bin/python3 -u main.py
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
EnvironmentFile=-/home/YOUR_USER/SignalBot1/.env

[Install]
WantedBy=multi-user.target
```

**/etc/systemd/system/signal-bot-2.service:**  
То же самое, замените путь на Signalbot2 и имя сервиса на `signal-bot-2`.

2. Включите и запустите (сначала первый, через несколько секунд второй):

```bash
sudo systemctl daemon-reload
sudo systemctl enable signal-bot-1 signal-bot-2
sudo systemctl start signal-bot-1
sleep 5
sudo systemctl start signal-bot-2
```

3. Просмотр логов:
```bash
journalctl -u signal-bot-1 -f
journalctl -u signal-bot-2 -f
```

4. Статус и перезапуск:
```bash
sudo systemctl status signal-bot-1 signal-bot-2
sudo systemctl restart signal-bot-1
```

## Проверка, что не зависает

- В логах за несколько секунд должны появиться строки вроде: «База данных инициализирована», «Бот запущен» (или «Bot 2 started»).
- Если лог обрывается на «подключении» к БД — проверьте `DATABASE_URL` (хост pooler.supabase.com, порт 6543, без плейсхолдеров).
- Если Supabase отвечает медленно — таймаут 15 секунд сработает и в логе будет явная ошибка вместо бесконечного ожидания.

## Кратко

| Проблема              | Решение                                      |
|-----------------------|----------------------------------------------|
| Долгое подключение к БД | `connect_timeout=15` в `database.py`         |
| Блокировка при init_db | `run_in_executor(None, init_db)` в `bot.py`  |
| Два бота бьют в БД сразу | Пауза 5 сек между стартами в скрипте         |
| Не видно, где зависло | Запуск через `python3 -u main.py`            |
| Надёжный автозапуск  | systemd, два сервиса, `Restart=on-failure`   |
